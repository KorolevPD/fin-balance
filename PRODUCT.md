# PRODUCT.md

## 1. Проблема и целевая аудитория

**Проблема**  
Владельцы банковских счетов регулярно выгружают выписки, но не могут быстро понять структуру своих расходов: операции имеют технические названия, большая часть попадает в «Прочие», а совместный учёт с членами семьи ведётся вручную в таблицах или не ведётся вовсе. В результате люди теряют контроль над бюджетом и не видят реальной картины трат.

**Целевая аудитория**  
Владельцы банковских счетов (физические лица 25–45 лет), которые:
- регулярно выгружают выписки (CSV/Excel);
- хотят видеть аналитику по категориям;
- живут в семье / паре / с родителями и нуждаются в совместном учёте расходов;
- не хотят платить за сложные финансовые сервисы и предпочитают простой инструмент.

## 2. Основной пользовательский сценарий

1. Пользователь регистрируется / входит в веб-приложение или через Telegram-бот.
2. Создаёт семью (группу) или присоединяется к существующей по коду/ссылке.
3. Загружает банковскую выписку (CSV или PDF).
4. Система парсит операции, пытается расшифровать технические названия и автоматически распределяет «Прочие» по категориям.
5. Пользователь видит дашборд: сумма расходов, топ-категории, список операций с понятными названиями.
6. Может вручную поправить категорию или название — система запоминает правки для будущих загрузок.
7. Члены семьи видят общие расходы (с возможностью фильтровать «мои / семейные»).

## 3. Функции MVP

**Обязательный минимум (2 дня):**
- Регистрация / вход (email + пароль или Telegram).
- Создание и присоединение к семейной группе (по коду).
- Загрузка банковской выписки в формате CSV (поддержка 1–2 популярных банков + универсальный шаблон).
- Парсинг CSV → список операций (дата, сумма, исходное описание, категория).
- Базовая категоризация по правилам + эвристикам (в т.ч. «Прочие»).
- Простая расшифровка названий операций (правила + словарь).
- Дашборд: общая сумма, разбивка по категориям (таблица + простой график), список операций.
- Возможность вручную изменить категорию и название операции.
- Общий просмотр расходов семьи (с фильтром «мои / все»).
- Telegram-бот: уведомления о загрузке, краткая сводка, возможность загрузить файл.

**Дополнительные фичи (3-й день, если успеем):**
- Улучшенная AI-категоризация и расшифровка через OpenCode / локальные правила.
- Экспорт отчёта.
- Простые уведомления в боте о превышении лимитов (если успеем).

## 4. Что не входит в MVP

- Поддержка PDF и сложных форматов выписок (только CSV).
- Автоматическая синхронизация с банками (Open Banking / API банков).
- Бюджетирование, цели, прогнозы, инвестиционные продукты.
- Мобильное приложение (только веб + Telegram).
- Сложные роли и права внутри семьи (все участники равны).
- Многовалютность и конвертация.
- Платные подписки и монетизация.
- Продвинутая аналитика (когорты, тренды по месяцам, сравнение с прошлыми периодами) — только базовая.
- Интеграция с внешними AI-сервисами, требующими платных ключей.

## 5. Проверяемые критерии готовности

- Пользователь может зарегистрироваться, создать семью и пригласить второго участника.
- Загрузка тестового CSV приводит к появлению ≥ 90 % операций в системе с датой, суммой и исходным описанием.
- Не менее 60 % операций из «Прочие» получают предложенную категорию (даже если не идеальную).
- Технические названия вида «P2P Ivanov I.» расшифровываются в понятный вид минимум в 50 % случаев по тестовому набору.
- Дашборд отображает корректную сумму и разбивку по категориям для загруженных данных.
- Второй участник семьи видит общие расходы.
- Telegram-бот принимает файл и возвращает краткую сводку.
- Всё разворачивается через Docker Compose и доступно по HTTP через nginx.
- Основные пользовательские сценарии проходят ручное тестирование без критических ошибок.

## 6. Технические и организационные ограничения

- Срок: 2 дня на MVP + 1 день на доработки.
- Команда: 7 человек.
- Стек: React (фронт), FastAPI (бэк), aiogram (Telegram-бот), PostgreSQL (или SQLite для простоты), nginx, Docker Compose, простой CI/CD.
- Запрещены платные AI-сервисы и API-ключи. Рекомендуется OpenCode и локальные/rule-based решения.
- Банковские выписки — только CSV, без реальных банковских API.
- Нет доступа к продакшен-инфраструктуре организаторов сверх базового.
- Данные пользователей считаются чувствительными → минимальное логирование, простая авторизация.

## 7. Риски продукта

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Разные форматы CSV у банков | Высокое | Поддержка 1–2 банков + универсальный шаблон + чёткая инструкция пользователю |
| Низкое качество автоматической категоризации и расшифровки | Среднее | Правила + ручная правка + запоминание правок пользователя |
| Пользователи не понимают, как выгрузить CSV | Среднее | Краткая инструкция + пример файла |
| Семейный учёт окажется сложнее, чем кажется | Среднее | Минимальная модель «все видят всё» без сложных прав |
| Нехватка времени на AI-часть | Высокое | AI — nice-to-have на 3-й день; в MVP достаточно правил |
| Проблемы с развёртыванием (Docker/nginx/CI) | Среднее | Заранее подготовить шаблон Docker Compose |
| Конфликт интересов внутри семьи (кто видит чьи траты) | Низкое (на MVP) | Прозрачность + возможность фильтровать «мои» |
