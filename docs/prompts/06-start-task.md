# Предварительные действия
Перед началом работы выполните анализ следующих артефактов проекта:
* AGENTS.md — руководство по взаимодействию с агентами;
* PRODUCT.md — описание продукта и его ключевых функций;
* Структура репозитория;
* Текущий git status для понимания состояния рабочей директории.

# Требования к документации
* Все создаваемые документы, комментарии и пояснения оформляются исключительно на русском языке.
* Для каждой итерации выполнения задачи создавайте новый файл по шаблону: `docs/agent/tasks/T-XXX/YYYYMMDDTHHMMSSZ_<OWNER>_aNN.md`, где:
    * T-XXX — идентификатор задачи;
    * YYYYMMDDTHHMMSSZ — временная метка в формате UTC;
    * <OWNER> — ваш идентификатор;
    * aNN — порядковый номер попытки выполнения.

# Ограничения и правила
* Не маркируйте функциональность как выполненную, если она не была протестирована или запущена.
* Не дублируйте текущий прогресс в PLAN.md — ведите актуальное состояние только в указанных выше файлах отчётов.
* Не добавляйте функциональность, которая не описана в PRODUCT.md — строго следуйте утверждённому объёму продукта.

# Процесс выполнения
1. Создайте отдельную ветку для реализации задачи.
2. После успешного завершения работы оформите все изменения в виде атомарных коммитов с осмысленными сообщениями.
3. По окончании создайте Pull Request (PR) с описанием внесённых изменений.

# Коммуникация
Если в процессе реализации возникают вопросы или неясности, задавайте их в чёткой, структурированной форме, ориентированной на пользователя. Избегайте технического жаргона, если это не требуется для понимания.
