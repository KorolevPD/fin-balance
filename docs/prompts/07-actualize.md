# Предварительные действия
Перед началом работы изучи все .md-файлы, код приложения, структуру репозитория и текущий git status.
На этом этапе запрещено изменять исходный код — работа ограничена анализом. 

# Требования к документации
* Все создаваемые документы, комментарии и пояснения оформляются исключительно на русском языке.
* Для каждой итерации анализа создавайте новый файл по шаблону:
    * `docs/agent/tasks/T-XXX/YYYYMMDDTHHMMSSZ_<OWNER>_aNN.md`, где:
    * T-XXX — идентификатор задачи;
    * YYYYMMDDTHHMMSSZ — временная метка в формате UTC;
    * `<OWNER>` — ваш идентификатор;
    * aNN — порядковый номер попытки.

# Задча
Выяви логические ошибки и несоответствия: расхождения документации с реализацией, противоречия в бизнес-логике, избыточные или недостающие сущности, архитектурные нестыковки. 
Подготовь структурированный отчёт с описанием проблем и предложениями по их устранению. 
Вноси минимальное количество правок — только необходимые для исправления без нарушения смежных компонентов. 

# Согласование и дальнейшие действия
После завершения анализа направьте подготовленный отчёт с предложениями на согласование пользователю.
Приступайте к внесению изменений в код исключительно после получения подтверждения.

# Коммуникация
При возникновении вопросов или неясностей в ходе анализа формулируйте их чётко и структурированно, ориентируясь на ясность для пользователя. Избегайте излишнего технического жаргона без необходимости.
