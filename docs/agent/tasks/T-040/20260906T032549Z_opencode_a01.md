## Цель выполнения

Изменить логику семейных групп: семья создаётся автоматически при
регистрации пользователя, у семьи нет названия, управление членами семьи
переносится в профиль пользователя, пункт «Создать семью» убирается из
хэдера.

## Решения по модели семьи (получены от пользователя)

- При присоединении по коду семьи объединяются. Пользователь может работать
  один (своя семья) или с командой до 5 человек.
- Страницы /family и /family/:id удаляются; их функционал переезжает в профиль.
- Названий семьи нет нигде: в модели, API и интерфейсе.

## Выполненные действия

1. Backend — модель Family: удалена колонка `name`. Создана миграция
   006_remove_family_name (drop column).
2. Backend — регистрация: автосоздание семьи владельцу через
   `create_default_family()` (auth.py).
3. Backend — роутер семей:
   - удалён `POST /families` (создание);
   - добавлен лимит `MAX_FAMILY_MEMBERS = 5`;
   - `POST /families/join`: при вступлении семьи объединяются — транзакции и
     члены переезжают в целевую семью, исходная семья удаляется, вступающий

4. Backend/бот: сообщения «Создайте или присоединитесь к семье» заменены на
   «семья создаётся автоматически при регистрации» (backend/app/routers/bot.py
   и bot/bot.py).
5. Frontend: из хэдера убран пункт «Создать семью».
6. Frontend: в Profile добавлен блок «Семья» — код приглашения с копированием,
   список участников, форма «Присоединиться к семье по коду».
7. Frontend: удалены страницы Families.js и FamilyDetail.js, маршруты /family и
   /family/:id убраны из App.js.
8. Frontend: Dashboard — заголовок «Дашборд расходов», ссылка «← Мой профиль»
   (без названия семьи).
9. Frontend: Upload — импорт всегда в единственную семью (без выбора и без
   автосоздания «Мои финансы»).
10. Тесты: обновлены существующие (убрано `name` у Family, роут без create),
    добавлены новые в tests/test_families.py (автосемья при регистрации,
    отсутствие названия в модели/API, объединение семей, перенос операций,
    неверный код 404, повторное вступление 409, лимит 5 участников).

## Ручная проверка (сценарий)

1. Регистрация нового пользователя → создаётся личная семья автоматически
   (критерий подтверждён тестом test_регистрация_создаёт_семью_владельцу).
2. Переход в профиль → блок «Семья» с кодом, участниками и формой вступления.
3. В хэдере навигация: «Загрузить», «Дашборд»; ссылка «Создать семью» отсутствует.
4. Второй пользователь вводит код первого → семьи объединяются, участников 2,
   у второго одна семья (критерий подтверждён тестом объединения).
5. Дашборд и загрузка не показывают название семьи.

Примечание: полная ручная проверка в браузере с живым backend не выполнялась
(только сборка и юнит/интеграционные тесты); сценарий выше описан для ручного
прогона координатором.

## Блокеры и риски

- Миграция 006 удаляет колонку `families.name` — для существующих баз данных
  названия семей будут потеряны (допустимо: названий больше не предусмотрено).
- Новая семья при регистрации: существующие пользователи (созданные до
  внедрения) автоматической семьи не получат — их семья появится либо при
  вступлении по коду, либо через ручную миграцию. Влияние ограничено
  прототипом.
