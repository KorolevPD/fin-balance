  локальными проверками; запуск полного стека — ручная проверка T-021.

### `backend/entrypoint.sh` (новый)

- Скрипт-инициализатор backend: ждёт готовности PostgreSQL (проверка
  `SELECT 1` с retry-циклом до 30 попыток / 60 с), затем применяет
  миграции `alembic upgrade head`, после чего `exec "$@"` (запускает CMD
  из Dockerfile / docker-compose). Без этого шага `docker compose up`
  поднимал бы API без схемы БД и все запросы падали.
- `backend/Dockerfile`: добавлены `ENTRYPOINT ["/app/entrypoint.sh"]`,
  `chmod +x` и `sed -i 's/\r$//'` (защита от CRLF на Windows-хостах).

### `bot/bot.py`: корректная деградация без токена

- `bot = Bot(token=BOT_TOKEN) if BOT_TOKEN else None` — с пустым
  `BOT_TOKEN` (значение по умолчанию в compose) объект Bot не создаётся.
- `main()`: при отсутствии бота пишет warning и переходит в фоновый цикл
  ожидания вместо `sys.exit(1)` — контейнер остаётся в статусе Up и не
  создаёт crash-loop при `docker compose up` без реального токена.

### `docker-compose.yml`

- Все настройки вынесены в интерполяцию `.env` с безопасными значениями
  по умолчанию: `POSTGRES_USER/PASSWORD/DB`, `SECRET_KEY`, `BOT_TOKEN`,
  `API_URL`.
- `db`: добавлен healthcheck (`pg_isready`), `backend` стартует только
  после `condition: service_healthy`.
- `frontend` (dev-сервер React, порт 3000) вынесен в `profiles: ["dev"]`:
  по умолчанию `docker compose up` поднимает прод-подобный стек db +
  backend + nginx + bot, а фронтенд отдаёт nginx из multi-stage сборки
  (T-019). Разработчики запускают dev-фронт через
  `docker compose --profile dev up`.
- Убран лишний `depends_on: frontend` у nginx.
- Добавлен `restart: unless-stopped` для всех сервисов.
- `db` больше не публикует порт 5432 на хост (БД только во внутренней
  сети compose) — наружу доступен только nginx (80) и backend (8000) для
  локальной отладки.
- Для nginx и bot убраны bind-mounts (`nginx.conf`, `bot/`) — код и
  конфиг логично собираются в образ при build (прод-подобная интеграция),
  как и было заложено в multi-stage Dockerfile nginx (T-019).

### `.env.example`

- Добавлены документированные переменные: PostgreSQL, `SECRET_KEY`,
  `BOT_TOKEN` (пустой = бот отключён), `API_URL`.

### `pyproject.toml`

- `extend-exclude = ["backend/entrypoint.sh"]` — иначе CI-линт

  Существующие ошибки ruff в backend (`models.py`, `alembic/*`,
