## Задача

По итогам ревизии кода исправить две логические ошибки (одобрено пользователем):

1. **П.1 (критично)** Веб-загрузка выписки не импортирует операции:
   `Upload.js` шлёт файл в `POST /upload`, который только сохраняет файл.
   Импорт есть в `POST /families/{id}/transactions/import`, но фронтенд его
   не вызывает и семью не выбирает.
2. **П.2+П.3** Тип «доход/расход» теряется: у `Transaction` нет колонки `type`,
   суммы хранятся по модулю, аналитика смешивает доходы с расходами.

## План (минимальные правки)

### Backend (П.2)
1. `Transaction.type` (String, default "expense") + миграция Alembic `005_add_transaction_type`.
2. `save_transactions` — записывать `type=item.type` (income/expense).
3. Роутер `transactions.py` — отдавать `type` в `TransactionOut` (list + patch).
4. `analytics.get_family_summary` — финансовые агрегаты считаются только по
   `type=="expense"` (total_amount, by_category, top_payees, monthly,
   family_members.total_expenses); `uploaded_files` считаются по всем операциям.

### Frontend (П.1)
5. `Upload.js` — выбрать семью (`/families/my`), отправить файл в
   `POST /families/{id}/transactions/import`, показать parsed/created/duplicates.

### Тесты
6. Обновить/добавить тесты: аналитика фильтрует доходы; веб-импорт не трогаем
   (frontend), но статус бэкенд-эндпоинта уже покрыт.
