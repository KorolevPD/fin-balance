# T-033 Попытка a02 — Hotfix: импорт sber.pdf через nginx

Владелец: opencode
Дата: 2026-09-06T06:25:00Z
Статус: REVIEW
Предыдущая попытка: T-033 a01 (парсер PDF), см. 20260905T142308Z_main_a01.md

## Проблема

Пользователь: маленькая выписка (8 операций) импортируется, а `examples/sber.pdf`
выдаёт в UI «Не удалось импортировать выписку».

## Диагностика

1. Парсер не виноват: `parse_pdf_bytes(sber.pdf)` → 255 операций (прошло ранее).
2. nginx без `client_max_body_size` → дефолт 1 МБ. `sber.pdf` = 1,43 МБ →
   загрузка через `POST /api/.../import` на порт 80 отдавала **HTTP 413**.
   Ответ nginx — HTML без JSON `detail`, поэтому `UploadModal.js` показывал
   fallback «Не удалось импортировать выписку».
3. После снятия лимита вскрылся второй, независимый дефект окружения:
   Docker Desktop (Linux) на этой машине НЕ передаёт большие тела запроса
   через опубликованный порт **80** (проверено: 800 КБ стабильно 408/обрыв),
   при этом порт **8000** и **8080** работают мгновенно. Внутри docker-сети
   nginx принимает тела 300 КБ+ и проксирует в backend без проблем.
   Вывод: проблема в host-форвардинге Docker Desktop именно на порту 80.

## Изменения

- `nginx/nginx.conf`: добавлен `client_max_body_size 50m;` в блок `http`.
- `docker-compose.yml`: host-порт nginx переведён с `80:80` на `8080:80`,
  т.к. на этой машине порт 80 не может передавать большие тела запросов
  (дефект Docker Desktop). Приложение доступно по http://localhost:8080/.

## Проверка

- Сквозной импорт реальной выписки через nginx:8080:
  регистрация → `/families/my` → `POST /families/{id}/transactions/import`
  с `examples/sber.pdf` → **201, parsed: 255, created: 255, duplicates: 0**.
- `curl POST :8080/api/x` c телом 800 КБ → 404 за 0,007 с (nginx проксирует).
- Тот же запрос в порт 80 → 408 по `client_body_timeout` (60 с) — воспроизводимо
  до и после правки лимита.
- `pytest tests/test_pdf_parser.py tests/test_transaction_router.py
  tests/test_upload_backend.py` → 25 passed.
- Тестовые импортированные транзакции удалены через
  `DELETE /families/{id}/transactions?source_file=sber.pdf` (deleted: 255).
