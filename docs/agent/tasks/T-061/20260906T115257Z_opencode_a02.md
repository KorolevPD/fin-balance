# T-061 (hotfix) — Дедупликация транзакций по пользователю

## Контекст

Продолжение задачи T-061 на ветке `feature/T-061-personal-family-toggle`
(отдельная ветка не нужна — правка лежит в том же сервисе).

**Проблема:** дедупликация в `save_transactions` выполняется в масштабе всей
семьи (`_existing_keys` фильтрует только по `family_id`). Если два участника
семьи загружают выписки с одинаковыми операциями (дата+сумма+описание),
вторая загрузка пропускает строки как дубли и операции остаются привязанными
к первому пользователю — «дубли засчитываются за одного».

**Решение (одобрено владельцем):** дедупликация по паре `family_id + user_id`;
семейная сводка «В семье» по-прежнему суммирует операции всех участников
(дубли разных пользователей учитываются по одному разу у каждого).

## Анализ

- `backend/app/services/transactions.py`:
  - `_dedup_key(day, amount, description)` → `(datetime, round(amount,2), description)`;
  - `_existing_keys(db, family_id, keys)` — фильтр только по `family_id`;
  - `save_transactions` вызывает `_existing_keys(db, family_id, unique.keys())`.
- `POST /families/join` переносит транзакции между семьями с сохранением
  `user_id` (families.py:136-138) — коллизий между пользователями не будет.
- Импорт в боте и в вебе идёт через тот же `save_transactions`.

## Реализация

1. `_existing_keys` — добавить параметр `user_id` и фильтр
   `Transaction.user_id == user_id`.
2. `save_transactions` — передавать `user_id` в `_existing_keys`.
3. Обновить docstring модуля.

## Тесты

- `test_transaction_service.py`: один и тот же набор операций у двух разных
  пользователей одной семьи создаётся для каждого (2 записи, своя привязка);
  повторный импорт тем же пользователем по-прежнему пропускается.
- `test_transaction_router.py`: два участника семьи импортируют одинаковый CSV —
