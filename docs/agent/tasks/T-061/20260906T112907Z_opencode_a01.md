# T-061 — Переключатель «В семье / Личные» на дашборде

## Контекст

**Проблема:** когда создаётся семья, на дашборде всегда показываются только
выписки всей семьи (`GET /families/{id}/summary` и `GET /families/{id}/transactions`
не фильтруют по пользователю). Пользователь теряет возможность просмотреть
свои личные выписки.

**Задача:** на окне «Общая сумма расходов» справа от текста добавить 2 большие
кнопки-переключателя «В семье» и «Личные». При переключении на «Личные»
показывать только выписки/агрегаты текущего пользователя, при «В семье» —
всей группы (текущее поведение).

Ветка: `feature/T-061-personal-family-toggle` (от `main`).

## Анализ кода

Backend:
- `backend/app/routers/transactions.py`:
  - `GET /{family_id}/transactions` — фильтр только по `family_id`
    (строки ~116–148).
  - `GET /{family_id}/summary` — вызывает `get_family_summary(db, family_id, current_user.id)`;
    `current_user.id` используется только для блока `uploaded_files`.
- `backend/app/services/analytics.py` — `get_family_summary(db, family_id, user_id=None)`:
  все агрегаты считаются по всем операциям семьи.

Frontend:
- `frontend/src/pages/Dashboard.js`:
  - блок «Общая сумма расходов» (строки 309–318, `summary-cards`/`stat-card`);
  - загрузка `GET /families/{id}/summary` и `GET /families/{id}/transactions`
    в `loadData` (строки 171–188);
  - `useAuth()` даёт `user` (в нём есть `id`).
- Стили: `frontend/src/styles.css` (один файл).

## Реализация

### Backend

1. В `list_transactions` добавить параметр `user_id: UUID | None = Query(None)`;
   при заданном значении добавить `Transaction.user_id == user_id` в фильтр.
2. В `family_summary` добавить параметр `user_id: UUID | None = Query(None)`;
   если задан — передавать его вместо `current_user.id` в `get_family_summary`
   как фильтр агрегатов.
3. В `analytics.get_family_summary` добавить флаг фильтрации по пользователю:
   изменить так, чтобы при указании `user_id` агрегаты считались только по
   операциям этого пользователя (и `uploaded_files` оставался для него же).

Примечание: поле `user_id` уже есть и в `Transaction`, и в `family_members`
(для отображения). Проверка доступа остаётся через `_require_membership`.

### Frontend

1. Добавить состояние `viewScope` (`'family' | 'personal'`), по умолчанию `'family'`.
2. В блок «Общая сумма расходов» добавить переключатель из двух больших кнопок
   «В семье» и «Личные`.
3. В `loadData` при `viewScope === 'personal'` передавать `user_id=<user.id>`
   в `GET /families/{id}/summary` и `GET /families/{id}/transactions`.
4. Перезагружать данные при смене переключателя.

## Замечание по аналитике

`uploaded_files` в `get_family_summary` вынесен в отдельный запрос и всегда
считается для запрашивающего `user_id` независимо от `filter_user_id` — иначе
при личном режиме блок «Банковские выписки» терял бы файлы текущего пользователя.
