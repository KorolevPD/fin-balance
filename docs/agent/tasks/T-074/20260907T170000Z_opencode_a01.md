## Проблема

Пользователь настроил GitHub Secret `GIGACHAT_CA_BUNDLE=/etc/ssl/certs/gigachat-ca.pem`,
но ошибка `CERTIFICATE_VERIFY_FAILED` повторялась. Причина:
- `deploy/deploy.sh` не принимал и не записывал переменную в `.env`.
- `.github/workflows/deploy.yml` не передавал секрет в deploy.sh.
- `docker-compose.prod.yml` уже содержал монтирование (из T-073), но без
  переменной окружения `_cacert()` возвращал `True` → certifi → тот же SSL-ошибку.

## План правок

- `deploy/deploy.sh`: добавлен 10-й аргумент `GIGACHAT_CA_BUNDLE`, запись в
  `.env`, fail-fast проверка наличия файла на хосте (`/etc/ssl/gigachat-ca.pem`).
- `.github/workflows/deploy.yml`: секрет добавлен в `env:`, `envs:` и аргументы
  скрипта.
- `deploy/DEPLOY.md`: последовательность шагов (файл на сервере → секрет → compose).

## Изменённые файлы

- `deploy/deploy.sh`
- `.github/workflows/deploy.yml`
- `deploy/DEPLOY.md`

## Проверка

## Действие на сервере (требуется от пользователя)

```bash
sudo openssl s_client -showcerts -connect ngw.devices.sberbank.ru:9443 \
  -servername ngw.devices.sberbank.ru -tls1_2 </dev/null 2>/dev/null \
  | sudo python3 -c "import sys,re; c=re.findall(r'-----BEGIN CERTIFICATE-----.*?-----END CERTIFICATE-----',sys.stdin.read(),re.S); open('/etc/ssl/gigachat-ca.pem','w').write(c[-1]+'\n')"
```

Или вручную: скачать PEM корня «НУЦ Минцифры России» с официального
распространителя доверенных корней и сохранить как `/etc/ssl/gigachat-ca.pem`.
