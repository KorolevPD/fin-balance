# T-031: Форма просмотра и редактирования профиля пользователя + фото

**Владелец:** opencode

**Попытка:** a01

## Задача

Создать форму просмотра и редактирования информации текущего пользователя,
а также возможность добавлять фото. Сейчас пользователь меняет имя и фото,
но форма проектируется расширяемой для будущих полей.

Стек: FastAPI (backend), React (frontend). Требования PRODUCT.md не добавляют
новых сущностей — задача является частью профиля пользователя (авторизация).

## План

### Backend
1. Модель `User.avatar` (stored_name файла фото) + миграция Alembic `004_add_user_avatar`.
2. `UserOut` — добавить поле `avatar`.
3. `PATCH /auth/me` — обновление полей профиля (сейчас `name`, схема расширяема).
4. `POST /auth/me/avatar` — загрузка фото (multipart), сохранение в `uploads/avatars/`,
   обновление `User.avatar`, возврат обновлённого `UserOut` с `avatar`.
5. Раздача аватаров: новый роут `GET /api/users/me/avatar-file/{...}` или
   StaticFiles mount `/api/uploads` — возврат изображения через FileResponse.
6. Валидация: допустимые типы изображений (jpeg/png/webp/gif), размер, безопасное имя.

### Frontend
1. Страница `Profile.js` — карточка с аватаром, имена полей; редактируемые поля
   (`name`) отображаются и сохраняются через `PATCH`. Фото загружается через
   `POST /auth/me/avatar` с предпросмотром.
2. Роут `/profile` (private) в `App.js`, ссылка в `Layout.js`, ссылка в шапке.
3. `AuthContext` — метод обновления пользователя после сохранения.
4. Стили в `styles.css`.

## Выполненные действия

### Backend
1. Модель `User.avatar` (строка stored_name фото) — `models.py`.
2. Миграция Alembic `004_add_user_avatar.py` (добавляет колонку `avatar`).
3. `UserOut` — добавлено поле `avatar`.
4. `PATCH /api/auth/me` — схема `UserUpdate` (`name`), сохраняет имя, возвращает `UserOut`.
5. `POST /api/auth/me/avatar` — multipart-загрузка фото, валидация типа (jpg/png/webp/gif)
   и размера (≤5 МБ), сохранение в `uploads/avatars/`, обновление `User.avatar`,
   удаление прежнего файла, возврат `UserOut`.
6. `GET /api/auth/me/avatar/{stored_name}` — отдача файла фото через `FileResponse`.
   Путь защищён от traversal через `sanitize_filename`.
7. `storage.py` — функции `save_avatar`, `avatar_path`, `avatar_dir`, `delete_avatar`,
   константы допустимых типов и размера.

### Frontend
1. `pages/Profile.js` — форма просмотра/редактирования: фото (предпросмотр + выбор файла),
   редактируемые поля конфигурируются массивом `EDITABLE_FIELDS` (сейчас `name`),
   неизменяемые поля — `READONLY_FIELDS` (email, дата регистрации), что упрощает
   добавление полей в будущем.
2. `App.js` — роут `/profile` (private).
3. `Layout.js` — ссылка «Профиль» в шапке, аватар пользователя в шапке (клик → профиль).
4. `AuthContext.js` — методы `updateUser` и `refreshUser`.
5. `styles.css` — стили `.profile-page`, `.profile-row`, `.avatar-*`, `.header-avatar*`, `.success`.
6. Пересобран `frontend/build/` (артефакты деплоя в nginx).
