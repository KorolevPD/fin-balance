## Цель выполнения

При загрузке PDF-выписки Сбербанка не все категории операций определяются,
хотя они указаны в выписке. Нужно использовать категорию из колонки
«КАТЕГОРИЯ» выписки и улучшить покрытие. Пример для работы — новый
`examples/sber.pdf` (12 страниц, 267 строк операций, 14 своих категорий).

## Диагностика (до изменений)

- Парсер PDF игнорирует колонку «КАТЕГОРИЯ», а категоризация ведётся только по
  ключевым словам описания (FIXPRICE, ISET TRANSPORT, BK BURGER RUS и т.п.).
- Результат по новому `sber.pdf`: 255 операций, из них 234 (91 %) «Прочее».
- Уже падают 3 существующих теста из-за обновлённого примера:
  - test_pdf_parser: «восем» операций (стало 255), числа доходов == 4 (стало >4);
  - test_transaction_router: import sber.pdf ожидал parsed==8.

## Решение (согласовано с пользователем)

1. Категория из выписки — главная: если она маппится на категорию приложения,
   используется она; правила по описанию — только если категория из выписки
   «Прочие операции»/«Прочие расходы» (generic) или отсутствует.
2. «Внесение наличных»/«Выдача наличных» → новая категория «Наличные»
   (добавляется в CATEGORY_RULES; фронтенд раскрашивает по палитре, брейков нет).

## Маппинг категорий Сбербанка → категории приложения

- Супермаркеты → Продукты
- Рестораны и кафе → Рестораны и кафе
- Транспорт → Транспорт
- Одежда и аксессуары → Одежда и обувь
- Отдых и развлечения → Развлечения
- Все для дома → Дом и ремонт
- Коммунальные платежи, связь, интернет. → Связь и интернет
- Аптеки и здоровье → Здоровье
- Перевод СБП / Перевод на карту / Перевод с карты → Переводы
- Внесение наличных / Выдача наличных → Наличные

## Реализация

- `backend/app/parsers/csv_parser.py`: у `ParsedTransaction` добавлено поле
  `statement_category: str | None = None` (pydantic, обратно совместимо).
- `backend/app/categorization/rules.py`: добавлены `SBERBANK_CATEGORY_MAP`
  (категории Сбербанка → категории приложения, см. «Маппинг») и категория
  `«Наличные»` в `CATEGORY_RULES` (ключевые слова: наличн/банкомат/atm).
  `GENERIC_STATEMENT_CATEGORIES` — комментарий-справка (не используется в коде,
  generic-категории просто не входят в маппинг).
- `backend/app/categorization/categorizer.py`: `categorize(description,
  statement_category=None)` — сначала `_map_statement_category` (приоритет
  категории из выписки), затем правила по ключевым словам, затем DEFAULT.
  `categorize_transactions` передаёт `item.statement_category`.
- `backend/app/parsers/pdf_parser.py`: колонка «КАТЕГОРИЯ» (group 3 строки
  операции) сохраняется в `statement_category`; `_DESCRIPTION_RE` смягчён с
  `\d{4,6}` на `\d{1,6}`, чтобы описание «Regular Charge …» с кодом «0»
  тоже извлекалось.

## Ручной сценарий (для проверки координатором)

1. Зарегистрироваться, загрузить examples/sber.pdf через дашборд.
2. Дашборд: категории «Продукты» (супермаркеты FIXPRICE/VERNYJ/MONETKA),
   «Транспорт» (ISET TRANSPORT), «Рестораны и кафе» (BK BURGER RUS/KFC),
   «Наличные» (внесение/выдача наличных), «Переводы» (СБП/переводы на карту).
3. Часть «Прочие операции» ушла в «Прочее» (снятия по договору, Альфа/Тинькофф).
4. Проверить, что суммы категорий совпадают с разбивкой в выписке.

## Непроверенные крайние случаи

- PDF других банков с колонкой «КАТЕГОРИЯ» (маппинг только для Сбербанка;
  неизвестная категория выписки не маппится → правила по описанию).
- CSV с колонкой «категория» (поле description из неё, привычное поведение).
- Сложные описания операций без категории выписки (правила без изменений).
