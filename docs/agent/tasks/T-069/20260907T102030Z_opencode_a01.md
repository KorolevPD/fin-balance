## Изменение подхода (по уточнению пользователя)

Источник сравнения — не имя аккаунта (`User.name`), а **владелец счёта из самой выписки**.

Выписка Сбербанка в шапке содержит строку «Владелец счёта», следующей строкой — ФИО владельца
(например «Иванов Иван Иванович»), это и есть эталон для сравнения с получателем перевода.

Что изменено:
- `backend/app/parsers/pdf_parser.py`: новая функция `extract_account_owner(data) -> str | None` —
  извлекает ФИО владельца счёта из шапки PDF; в CSV-форматах владелец в файле не указывается,
  поэтому для CSV эталон отсутствует и переводы не помечаются.
- `backend/app/parsers/__init__.py`: экспорт `extract_account_owner`.
- `backend/app/routers/transactions.py`: `_parse_file` возвращает `(операции, владелец)`;
  `mark_self_transfers(parsed, owner)` вызывается с владельцем из выписки, а не из аккаунта.
- `backend/app/routers/bot.py`: убран вызов `mark_self_transfers` (бот принимает только CSV,
  владельца из файла получить нельзя).
- `tests/test_self_transfers.py`: добавлен `TestExtractAccountOwner`; интеграционные тесты
  импортируют реальный `examples/sber.pdf` и проверяют, что перевод «Перевод для И. Иван
  Иванович» помечается, а «Перевод для М. Ксения Андреевна» — нет; имя аккаунта на результат
  не влияет.

Логика `names.py` не менялась: `mark_self_transfers(transactions, owner_name)` уже принимает
имя владельца как параметр.

Проверка: `pytest` — 210 passed, ruff чист по изменённым файлам, фронтенд не менялся.
