## Выполненные действия

**CI/CD и деплой:**
- Создан `.github/workflows/deploy.yml`: при push/merge в `main` и при ручном запуске подключается к серверу по SSH (webfactory/ssh-agent), копирует `deploy/deploy.sh`, `docker-compose.yml`, `nginx`, затем через appleboy/ssh-action выполняет скрипт деплоя с секретами из GitHub Actions.
- Создан `deploy/deploy.sh`: принимает секреты аргументами, пишет `.env` на сервере, собирает и поднимает стек через `docker compose -f docker-compose.yml -f docker-compose.prod.yml`.
- Создан `docker-compose.prod.yml`: продакшен-переопределения — отключён dev (bind-mount, `--reload`), backend `expose` без публикации порта наружу, наружу смотрит только nginx (порт `DEPLOY_PORT`, по умолчанию 80).
- Создан `deploy/DEPLOY.md`: подробная инструкция «что нужно от пользователя» — IP/хост, SSH-пользователь/порт/приватный ключ, ОС, домен; список всех GitHub Actions secrets; шаги первичной настройки сервера (Docker); рекомендации по HTTPS/certbot как отдельной задаче.

**Серверный Gemini-ключ:**
- Новый модуль `backend/app/ai/server_key.py`: `server_gemini_key()` и `has_server_gemini_key()` читают `GEMINI_API_KEY` из окружения.
- `backend/app/ai/__init__.py`: экспорт новых хелперов.
- `backend/app/services/ai_transactions.py::enrich_saved_transactions`: если задан серверный ключ — используется он (provider=gemini), иначе — ключ пользователя.
- `backend/app/routers/ai.py::create_advice`: аналогично, при серверном ключе совет генерируется им; без серверного — ключом пользователя.
- `backend/app/routers/auth.py`: `UserOut.server_ai_key` (признак активного серверного ключа, отдаётся в `/auth/me` и `/auth/me` PATCH); в `update_me` при заданном серверном ключе запрещено сохранять свой ключ (HTTP 400 «Используется серверный AI-ключ…»).
- `docker-compose.yml`, `.env.example`, `backend/.env.example`: добавлена `GEMINI_API_KEY`.

**Frontend:**
- `frontend/src/pages/Profile.js`: при `user.server_ai_key === true` блок ввода AI-ключа скрыт, показывается сообщение «AI-ключ предоставляется сервером…»; при пустом серверном ключе форма ввода ключа пользователя как раньше.

**Тесты (новые):**
- `tests/test_profile.py::TestServerAiKey`: флаг `server_ai_key` в `/me` (вкл/выкл), запрет сохранения своего ключа при серверном, разрешение при его отсутствии.
- `tests/test_ai_advices.py::TestServerKeyAdvice`: совет генерируется серверным ключом (provider=gemini, без ключа пользователя).
