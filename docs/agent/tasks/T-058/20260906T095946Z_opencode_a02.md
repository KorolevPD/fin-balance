CONFLICTING. Причина: ветка создана от `90c3b10`, а `main` ушёл вперёд

## Диагностика

- `git merge-tree base main ветка` показал конфликты «changed in both» только в
  сгенерированных build-файлах:
  - `frontend/build/asset-manifest.json`
  - `frontend/build/index.html`
- `frontend/src/styles.css`: и ветка (градиент `.dashboard`, строки 131–140), и
  main (`.files-remove-cell`, строка ~797) меняют разные участки одного файла —
  merge пройдёт чисто (в merge-tree нет маркеров `<<<<<<<` для styles.css).
- Ветка добавляет `docs/agent/tasks/T-058/20260906T093405Z_main_a01.md` (чисто).

## Решение

1. `git merge origin/main` на ветке `feat/diagonal-gradient-background`.
2. Резолв конфликтов только в `frontend/build` (hash-файлы): взять рабочие
   версии так, чтобы после пересборки бандл содержал и градиент ветки, и
   изменения main (см. прецедент T-045 a02 — конфликты только в build,
   исходники мержатся чисто).
3. Пересобрать `npm run check` из смерженного исходника — build перепишется
   целиком (новые хеши).
4. Коммит-merge с двумя родителями → `origin/main` становится предком ветки.
5. Push + проверка `gh pr view 65` → mergeable=CLEAN.
