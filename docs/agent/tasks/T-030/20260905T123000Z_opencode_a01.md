# T-030: Реальный бэкенд дашборда и привязка фронтенда

**Владелец:** opencode
**Дата:** 2026-09-05T12:30:00Z
**Попытка:** a01

## Задача

Сделать реальный бэкенд для 4-блочного дашборда и привязать к нему фронтенд.
Макет (из T-029): члены семьи с тратами, круговая диаграмма категорий,
загруженные файлы, пустой блок. Дашборд живёт на `/family/:id/dashboard`.

Решение пользователя:
- Обновить семейный `/family/:id/dashboard` (реальный дашборд).
- Добавить поле `name` в модель `User`.

## План

1. Модель `User.name` + миграция Alembic `003_add_user_name`.
2. Auth: регистрация принимает `name`, `UserOut` отдаёт `name`.
3. Familise: `MemberOut` + `name`.
4. Аналитика: расширить `get_family_summary(db, family_id, user_id)`:
   - `family_members` — члены семьи с суммарными тратами (сортировка по убыванию);
   - `uploaded_files` — файлы текущего пользователя: filename, период
     (первая/последняя операция), количество операций.
5. Вызовы в `transactions.py` и `bot.py` — передать `user_id`.
6. Фронтенд `Dashboard.js` — 4-блочная сетка с реальными данными, ниже
   сохранены существующие секции (общая сумма, категории, динамика,
   топ получателей, список операций с редактированием).
7. Регистрация (Register + AuthContext) — поле «Имя».
8. Layout — вывод `user.name`.
