## Выполненные действия

1. Запустил `docker compose up -d` — backend вошёл в crash-loop с
   `exec /app/entrypoint.sh: no such file or directory`.
   Диагноз: `docker-compose.yml` подключает bind-mount `./backend:/app`,
   который в рантайме перекрывает файл entrypoint.sh из образа. В рабочей
   копии на Windows файл имеет CRLF (`core.autocrlf=true`), поэтому
   shebang превращается в `#!/bin/sh\r`, и ядро Linux не находит
   интерпретатор (симптом «no such file or directory», а не «permission
   denied»). Образный `sed -i 's/\r$//'` внутри Dockerfile при этом
   бесполезен — bind-mount подставляет CRLF-версию.
2. Промежуточно пробовал запускать entrypoint через `["/bin/sh", ...]`:
   онагики CRLF в ядре ушли, но dash не понял `set -e\r` (Illegal option -).
   Откатил этот вариант (не оставил в diff).
3. Финальное решение: `.gitattributes` c `*.sh text eol=lf` заставляет Git
   при checkout выдавать LF независимо от `core.autocrlf` на Windows —
   восстановил большой `ENTRYPOINT ["/app/entrypoint.sh"]`, нормализовал
   index-блоб entrypoint.sh через `git add --renormalize` + `checkout`, и
   явно убрал CRLF в рабочей копии (`sed -i 's/\r$//'`).
4. После подъёма backend обнаружил второй баг: `backend/main.py:29`
   использует `bot.router` без импорта
   (`NameError: name 'bot' is not defined`). Роутер существует в
   `backend/app/routers/bot.py` (T-016), но не был импортирован.
   Добавил `bot` в `from app.routers import ...`.
5. Полный прогон стека после фиксов — все сервисы Up, API и nginx
   работают end-to-end (см. «Команды и результаты»).
6. `docker compose down` после проверки (стек поднят вручную для теста).
