## Задача пользователя

В форме «Редактирование операции» должна быть возможность вручную запустить
генерацию ИИ-описания названия операции. Дизайн кнопки — как в блоке «Совет от
AI» на дашборде. Результат НЕ сохраняется автоматически: ответ ИИ заполняет
поле «Название», пользователь сам решает, нажимать ли «Сохранить».

## План

### Backend

1. `backend/app/services/ai_transactions.py`:
   - Новая функция `generate_single_description(*, transaction, user) -> str`:
     - выбирает ключ (server key GigaChat или ключ пользователя), как в
       `enrich_saved_transactions`;
     - вызывает `classify_descriptions` для одной операции;
     - возвращает нормализованный `cleaned_description`;
     - при отсутствии ключа — `ValueError` («AI не настроен»);
     - при ошибке/пустом ответе — `AIError` (пробросить с пояснением).
   - Общая логика выбора ключа дублируется минимально (не переписываем
     существующую `enrich_saved_transactions`).
2. `backend/app/routers/transactions.py`:
   - Pydantic-модель ответа `AIDescription { cleaned_description: str }`;
   - `POST /{family_id}/transactions/{transaction_id}/ai-description`:
     - `_require_membership`, поиск транзакции (`404` если нет);
     - `ValueError` → `400`, `AIError` → `502`;
     - возврат `{"cleaned_description": ...}`.
3. Тесты `tests/test_ai.py` (или новый блок):
   - эндпоинт генерирует описание (мок httpx) и НЕ изменяет транзакцию в БД;
   - без AI-ключа → `400`.

### Frontend

4. `frontend/src/components/TransactionEditModal.js`:
   - состояние `generating` и обработчик `handleGenerate` (POST к
     `ai-description` эндпоинту; результат → `setTitle`; ошибка → `setError`);
   - в поле «Название» рядом с input — кнопка-иконка как в блоке «Совет от AI»
     (класс `advice-generate-btn`, `<img src="/pale-button.png">`), с
     `title`/`aria-label`, disabled во время генерации.
5. `frontend/src/styles.css`:
   - контейнер `.field-with-action { display: flex; gap: 8px; }` с
     `input { flex: 1; }`, чтобы кнопка стояла в ряду с полем.

## Проверка

- Backend: `pytest tests/test_ai.py`, затем весь `pytest`; `ruff check`.
- Frontend: `npm run check`, `CI=true npx react-scripts test`.
- Ручной сценарий (браузер): в форме «Редактирование операции» нажать
  иконку-кнопку → поле «Название» заполняется ИИ-описанием; до нажатия
  «Сохранить» в БД ничего не меняется; при отсутствии ключа — понятная ошибка.

### Ручной сценарий (браузер, для проверки пользователем)

- В списке операций (дашборд или «Все операции») нажать «Изменить».
- В форме «Редактирование операции» в поле «Название» нажать иконку-кнопку
  (зелёная окантовка, pale-button.png): идёт генерация (кнопка disabled),
  затем поле «Название» заполняется ИИ-описанием; фокус остаётся в поле.
- Фоновая сущность операции в БД НЕ меняется: изменения применяются только по
  кнопке «Сохранить». Пользователь может отредактировать текст или нажать
  «Отмена».
- Без ключа GigaChat в профиле приходит ошибка
  «AI не настроен. Добавьте ключ GigaChat в профиле.»
- Фактический запуск браузера из CLI невозможен — требуется ручная проверка.
