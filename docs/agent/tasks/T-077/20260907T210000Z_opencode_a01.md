## Задача пользователя

1. AI-обработка описаний операций упирается в «Too Many Requests» (HTTP 429).
   Нужно обрабатывать операции пачками.
2. Категории также обрабатывать пачками, где возможно.
3. В карточке «Редактирование операции» показывать заблокированное поле
   «Оригинальное название», если у операции есть сгенерированное ИИ название.
4. Сгенерированное описание должно быть максимально точным, не менять суть
   операции, а форматирование — грамотным (без пропусков точек/запятых).

## Анализ текущего кода

- Фоновая догрузка AI (`app/services/ai_transactions.py::enrich_saved_transactions`)
  передаёт ВСЕ операции категории «Прочее» выписки одной пачкой в
  `classify_descriptions` → `gigachat.classify_transactions` → один HTTP-запрос
  `_chat`. Большая выписка (десятки–сотни операций) превышает лимиты GigaChat
  (RPM/токены) → HTTP 429 «Too Many Requests».
- `enrich_with_ai` (синхронный путь, сейчас используется только в тестах)
  страдает тем же.
- Категории и описания присваиваются одним и тем же ответом
  `ClassifyResult(category, cleaned_description)` — пакетная обработка закрывает
  оба пункта (2) и (1) сразу.
- Модель Transaction хранит `original_description` и `cleaned_description`;
  API `TransactionOut` возвращает оба поля, фронтенд-модалка
  `TransactionEditModal.js` их получает.

## План реализации

### Backend — пакетная обработка (пункты 1 и 2)

- `backend/app/ai/gigachat.py`:
  - `CLASSIFY_BATCH_SIZE = 30`, `_CHAT_MAX_ATTEMPTS = 4`, `_RETRY_BASE_DELAY = 1.0`.
  - `_chat` разделён: токен запрашивается один раз, `_chat_with_token`
    выполняет запрос(ы) к `/chat/completions` с повтором на HTTP 429
    (экспоненциальная пауза).
  - `classify_transactions` нарезает описания на пачки по
    `CLASSIFY_BATCH_SIZE`, каждую пачку — отдельным запросом, результаты
    склеиваются с сохранением порядка. При ошибке пачки — `AIError`
    (фолбэк на правила, как и раньше).

### Backend — промпт (пункт 4)

- `backend/app/ai/_common.py::build_classify_prompt`: добавить требования
  «сохраняй суть операции, не додумывай детали» и «грамотная пунктуация
  (точки, запятые, пробелы, заглавная буква)». Условия существующих тестов
  («Прочее» и «если не уверен» отсутствуют в промпте) сохраняются.

### Frontend (пункт 3)

- `frontend/src/components/TransactionEditModal.js`: если
  `transaction.cleaned_description` непустое (сгенерированное ИИ название),
  вывести заблокированное поле «Оригинальное название» со значением
  `transaction.original_description`.

## Тесты (добавить в tests/test_ai.py)

- `test_classify_transactions_разбивает_на_пачки`: размер пачки 2, 5 описаний →
  3 вызова `/chat/completions`, результат 5 записей, порядок сохранён.

### Ручной сценарий (браузер, для проверки пользователем)

- Открыть операцию с категорией «Прочее» после AI-догрузки: в карточке
  «Редактирование операции» видно заблокированное поле «Оригинальное название»
  с техническим названием и редактируемое поле «Название» с расшифровкой.
- Для операции без AI-расшифровки заблокированного поля нет.
- Импорт большой выписки (например, 200+ записей «Прочее») проходит без
  «Too Many Requests»: фоновая догрузка режет операции на пачки по 30 и
  повторяет запрос при HTTP 429.
