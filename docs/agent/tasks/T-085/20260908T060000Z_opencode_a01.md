# T-085: не загружать переводы самому себе при импорте PDF

- Дата: 2026-09-08T06:00:00Z
- Владелец: opencode
- Ветка: feature/T-085-dont-import-self-transfers (от main)
- Предыдущая попытка: нет

## Задача пользователя

При парсинге PDF должны определяться переводы самому себе в другой банк.
На первом листе есть поле «Владелец счёта» с ФИО; в операциях перевода тоже
есть ФИО, но в другом формате (например, «Иванов Иван Иванович» в шапке и
«И. Иван Иванович» в операции). При загрузке файла приложение должно на основе
парсинга определить ФИО владельца и НЕ загружать операции переводов с таким же
ФИО.

Реальный пример: владелец «Иванов Иван Иванович», операция «Перевод для
И. Иван Иванович» — перевод самому себе, загружать не нужно.

## Контекст (что уже есть)

- `backend/app/parsers/pdf_parser.py`:
  - `extract_account_owner(data)` — извлекает ФИО владельца из шапки «Владелец
    счёта»;
  - `parse_pdf_bytes(data)` — возвращает все операции (переводы себе НЕ
    исключает).
- `backend/app/services/names.py`:
  - `is_transfer_to_self(owner_name, description)` — по признакам ФИО
    (имя/отчество/первая буква фамилии) определяет перевод самому себе.
    Работает и для «И. Иван Иванович» (инициал фамилии + имя + отчество);
  - `mark_self_transfers(transactions, owner_name)` — помечает
    `is_self_transfer=True`.
- `backend/app/routers/transactions.py` (`import_transactions`):
  - `mark_self_transfers(parsed, owner_name)` вызывается, но операции
    САМУ СЕБЕ сохраняются в БД (только помечаются флагом), а из аналитики
    исключаются.
- Тесты `tests/test_self_transfers.py` ожидают сохранение self-transfer с
  флагом.

## Изменения

### Код

- `backend/app/routers/transactions.py`, `import_transactions`:
  после `mark_self_transfers(parsed, owner_name)` отфильтровать операции
  с `is_self_transfer=True` — такие переводы не попадают в `save_transactions`
  (не загружаются). Для CSV владелец не известен (owner_name=None) — поведение
  не меняется.

### Тесты

- `tests/test_pdf_parser.py`, `tests/test_self_transfers.py`,
  `tests/test_transaction_router.py`: обновить путь к примеру
  `examples/sber.pdf` → `pdf_examples/sber.pdf` (каталог переименован в
  репозитории, сейчас, без правки пути тесты падают с FileNotFoundError).
- `tests/test_pdf_parser.py`: `len(transactions) == 255` → `== 249`
  (актуальное число операций из нового примера; парсер по-прежнему возвращает
  все операции, включая self-transfer).
- `tests/test_transaction_router.py`: в `test_импорт_pdf_выписки_создаёт_транзакции`
  ожидания `parsed`/`created` 255 → 243 (249 − 6 self-transfer).
- `tests/test_self_transfers.py`:
  - заменить `test_импорт_помечает_перевод_самому_себе_по_владельцу_из_выписки`
    на проверку НОВОГО поведения: перевод «Перевод для И. Иван Иванович» НЕ
    загружается (отсутствует в списке транзакций), перевод другому человеку
    «Перевод для М. Ксения Андреевна» есть;
  - `test_сводка_не_учитывает_перевод_самому_себе` — оставить (семантика
    расходов не меняется).

### Ручной сценарий (требуется проверка пользователем)

- Загрузить real PDF-выписку: переводы с ФИО владельца («Перевод для И. Иван
  Иванович») отсутствуют в списке операций и не влияют на сумму расходов;
  переводы другим людям загружаются.
- Сумма расходов на дашборде не считает переводы самому себе.

### Непроверенные крайние случаи

- Переименование каталога `examples`→`pdf_examples` выполнено в тестах, но
  в документации (docstring pdf_parser.py упоминает `examples/sber.pdf`) —
  оставлено как есть (документация, не влияет на чтение).
