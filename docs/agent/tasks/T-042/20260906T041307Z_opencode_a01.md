## Решение по пагинации

Пагинация на клиенте:

- `Operations.js` один раз получает список существующим эндпоинтом
  `GET /families/{id}/transactions`, сортирует по дате «сначала новые»
  (как на дашборде по умолчанию) и разбивает по 50 на странице;
- дашборд показывает первые 10 из отсортированного списка, а в заголовке
  «Операции (N)» остаётся общее число операций;
- backend не меняется → API, бот и существующие pytest не затрагиваются.

## Ручной сценарий проверки в браузере

1. Настроить данные: загрузить CSV с >50 операциями (например, файлом или
   повторными импортами).
2. Открыть /family/:id/dashboard → раздел «Операции» показывает ровно 10
   операций (самые новые), в заголовке «Операции (N)» — общее число N.
3. Клик «Все операции →» → открывается /family/:id/operations.
4. На странице: операций на странице 50, «Страница 1 из P».
5. «Далее →» переводит на страницу 2 (другие 50), «← Назад» возвращает;
   на первой странице «Назад» и на последней «Далее» отключены.
6. Клавиатура: Tab до кнопок пагинации, Enter/пробел переключают страницы.
7. «Изменить» на любой операции открывает модалку; сохранение обновляет
   список.

## Блокеры и риски

  росте данных — отдельная задача на серверную пагинацию.
- Ручная проверка в живой браузерной сессии не выполнялась; сценарий выше
  описан для ручного прогона координатором.
