# T-062: Фикс: некорректное отображение даты регистрации

**Попытка:** a02
**Владелец:** opencode
**Начало:** 2026-09-06T12:40:00Z

## Предыдущая попытка

a01 (`20260906T123000Z_opencode_a01.md`): была заменена строка `type: 'date'` на `type: 'text'` в `READONLY_FIELDS` (строка 12). После этого на строке 410 условие `field.type === 'date'` стало всегда ложным, и `formatDate()` перестал вызываться вовсе. В профиле стала отображаться сырая ISO-строка (`2026-09-06T10:30:00`).

## Что сделано

- Исследована первопричина: в `Profile.js:410` условие `field.type === 'date' ? formatDate(...) : user?.[field.key]` — при `type: 'text'` (текущее значение для `created_at`) `formatDate()` не вызывается, пользователь видит сырой ISO-формат с лишними символами (`T`, время).
- Применено минимальное исправление в `Profile.js:410`:
  ```diff
  - value={field.type === 'date' ? formatDate(user?.[field.key]) : user?.[field.key]}
  + value={formatDate(user?.[field.key]) || user?.[field.key]}
  ```
- `formatDate()` вызывается для всех readonly-полей. Для `email` она возвращает `''` (falsy) → показывается оригинальное значение email. Для `created_at` — возвращает `06.09.2026` (ru-RU, `день.месяц.год`).
- `type` остаётся `'text'`, поэтому браузер не игнорирует значение с точками (как было бы с `<input type="date">`, требующим `YYYY-MM-DD`).
- Проверка: `npm run check` — Compiled successfully.

Зарегистрировать нового пользователя, войти в профиль `/profile`, секция «Данные аккаунта» → поле «Дата регистрации» должно показывать `дд.мм.гггг` (например, `06.09.2026`) без времени и буквы `T`.
