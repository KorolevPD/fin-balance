# Стартовый проект для работы с кодовыми агентами

Это минимальный проект для практики управляемого вайб-кодинга с OpenCode. В нём уже есть:

- правила для агента в `AGENTS.md`;
- продуктовый документ `PRODUCT.md`;
- план реализации и тестирования `PLAN.md`;
- журнал конкретных задач `TASKS.md`;
- отдельные timestamp-файлы для каждой попытки выполнения;
- шаблоны промптов;
- иерархические правила для исходного кода и тестов;
- инструкция по бесплатным моделям OpenCode Zen;
- планирование в Qwen Chat или GigaChat;
- рекомендация хранить проект в GitVerse;
- отключённые примеры Context7, grep.app и CodeGraph;
- простое браузерное приложение без внешних зависимостей.

## Главное правило

Все создаваемые агентом документы, планы, отчёты, статусы и пояснения должны быть написаны **на русском языке**. Технические имена файлов, команд, API и идентификаторов кода переводить не нужно.

## Сначала опишите продукт и план вне OpenCode

До запуска кодового агента подготовьте в Qwen Chat или GigaChat два файла:

- `PRODUCT.md` — что и для кого создаётся;
- черновой `PLAN.md` — как реализовать и проверить.

Это позволяет не расходовать бесплатные обращения модели-исполнителя на длинное обсуждение идеи и первичную декомпозицию.

Рекомендуемый порядок:

1. Войдите в Qwen Chat: без авторизации гостевой лимит может закончиться быстрее.
2. Создайте отдельный Workspace для проекта и загрузите только разрешённые материалы.
3. Используйте `prompts/01-product-plan.md`.
4. Сохраните результат в `PRODUCT.md` и `PLAN.md` на русском языке.
5. Не загружайте `.env`, API-ключи, токены и персональные данные.
6. Если Qwen недоступен, используйте GigaChat с тем же промптом.
7. Только после проверки документов запускайте OpenCode.

## Git и GitVerse

Для курса рекомендуется GitVerse как удалённый Git-репозиторий. Создайте репозиторий до запуска агента, сохраните исходное состояние и делайте commit после каждого проверенного шага.

```bash
git init
git add .
git commit -m "init: каркас проекта"
git branch -M main
git remote add origin <URL-репозитория-GitVerse>
git push -u origin main
```

Никогда не добавляйте в GitVerse `.env`, API-ключи и токены.

## Быстрый старт

1. Установите Node.js 20 или новее.
2. Откройте каталог проекта в терминале.
3. Проверьте исходное состояние:

```bash
npm test
npm run check
```

4. Запустите статический сервер:

```bash
python3 -m http.server 8000
```

5. Откройте `http://localhost:8000`.
6. Запустите OpenCode из корня проекта:

```bash
opencode
```

7. Попросите агента прочитать `AGENTS.md`, `PRODUCT.md`, `PLAN.md` и `TASKS.md`.

## Как начать новую задачу

1. Подготовьте `PRODUCT.md` и черновой `PLAN.md` в Qwen Chat или GigaChat.
2. В режиме Plan OpenCode проверьте план по репозиторию и создайте `TASKS.md` с помощью `prompts/02-create-task-plan.md`.
3. Проверьте документы вручную.
4. Перед реализацией создайте `docs/agent/tasks/T-XXX/YYYYMMDDTHHMMSSZ_<OWNER>_aNN.md`.
5. Попросите OpenCode выполнить только одну текущую задачу.
6. Проверьте `git diff` и тесты; только координатор обновляет `TASKS.md`.

## Как продолжить после перезапуска

Используйте `prompts/03-continue.md`. Агент должен восстановить состояние из файлов и Git, создать новый timestamp-файл и продолжить с точного следующего шага, а не планировать проект заново.

## Иерархические инструкции

- `AGENTS.md` — общие правила проекта.
- `src/AGENTS.md` — правила исходного кода.
- `tests/AGENTS.md` — правила тестирования.
- `docs/rules/*.md` — подробные инструкции, которые читаются только по необходимости.

Корневой `AGENTS.md` действует как навигатор. Не загружайте все инструкции в контекст заранее.

## Бесплатные модели OpenCode Zen

```text
/connect → OpenCode Zen
/models  → Muse Spark 1.3 Contributor Free
```

На дату подготовки комплекта — **3 сентября 2026 года** — OpenCode Zen перечисляет несколько бесплатных моделей. Практический старт для coding-agent сценария — **Muse Spark 1.3 Contributor Free**; универсальный резерв — **MiMo-V2.5 Free**.

Бесплатные модели доступны ограниченное время. Список, скорость и условия обработки данных могут измениться. Перед занятием обязательно проверьте `/models` и не отправляйте секреты или закрытый код.

Для проверки сложного diff по возможности используйте модель другого производителя: разные семейства моделей имеют разные типичные ошибки. Это дополнительный взгляд, а не замена тестам.

См. `docs/OPENCODE_FREE_MODELS.md`.

## MCP, LSP и CodeGraph

- Context7 помогает получить документацию нужной версии.
- grep.app ищет примеры в открытом коде.
- CodeGraph строит граф файлов, символов, вызовов и зависимостей.
- LSP показывает определения, ссылки, типы и диагностику.

Все MCP в `opencode.jsonc` отключены по умолчанию. Включайте только необходимые. См. `docs/MCP_LSP_CODEGRAPH.md`.

## Безопасность skills

В архив не включены сторонние skills. Skill может содержать не только инструкции, но и исполняемые scripts. Перед установкой проверяйте исходный код, команды, сетевые обращения и необходимые разрешения.

См. `docs/SKILLS_SECURITY.md`.
