# FinBalance

Совместный учёт семейных расходов на основе банковских выписок. Пользователь загружает выписку в формате CSV или PDF, система парсит операции, автоматически распределяет их по категориям и показывает аналитику на дашборде. Правки пользователя запоминаются для следующих загрузок.

## Описание

Владельцы банковских счетов регулярно выгружают выписки, но не могут быстро понять структуру расходов: операции имеют технические названия, большая часть попадает в «Прочее», а совместный учёт с членами семьи ведётся вручную. FinBalance решает эту задачу:

- загрузка выписки в формате CSV или PDF;
- парсинг операций (дата, сумма, описание, тип операции) с поддержкой Сбербанка и универсального шаблона;
- автоматическая категоризация по правилам и словарям, в том числе расшифровка технических названий («P2P Ivanov I.» → понятное описание);
- дашборд с суммой расходов, разбивкой по категориям, динамикой баланса и топ-5 получателей;
- ручное редактирование категории и названия операции — правки запоминаются через `UserCorrection`;
- семейный учёт: все участники видят общие расходы, доступен переключатель «В семье / Личные»;
- загрузка выписки через Telegram-бот и краткая сводка по команде `/summary`;
- опциональная AI-категоризация и советы через API-ключ GigaChat (Authorization Key) или серверный ключ;
- перераспределение операций из «Прочее»: AI уточняет категорию при наличии ключа, иначе операции остаются как есть.

Полное описание продукта, сценарии и критерии готовности — в `PRODUCT.md`.

## Технологический стек

| Слой | Технологии |

| Качество | pytest, ruff, ESLint, react-scripts test |

## Бизнес-логика

**Домены и модули backend:**

- `auth` — регистрация, вход, JWT-токены, профиль (имя, фото, настройки AI-ключа).
- `families` — семейные группы: семья создаётся автоматически при регистрации, присоединение по коду приглашения (лимит 5 участников), выход из семьи.
- `transactions` — загрузка выписок, парсинг CSV/PDF, сохранение операций, дедупликация по паре «семья + пользователь», редактирование и удаление.
- `categorization` — правила категоризации, расшифровка названий, запоминание правок пользователя.
- `analytics` — агрегации для дашборда: общая сумма, категории, динамика баланса, топ-5 получателей, расходы по участникам.
- `ai` — AI-классификация операций при импорте, советы в блоке «Резерв», интеграция GigaChat и фолбэк на правила.
- `bot_integration` — эндпоинты, которые вызывает Telegram-бот.

**Ключевые правила:**

- Семья создаётся автоматически при регистрации; при отсутствии семей форма загрузки автосоздаёт семью «Мои финансы».
- Категории присваиваются по правилам ключевых слов; для PDF-выписки Сбербанка категория из выписки имеет приоритет.
- Участники видят общие расходы семьи; фильтр «Личные» показывает только операции пользователя (запрос чужих данных запрещён — 403).
- AI-ключ пользователя хранится зашифрованным (AES-GCM, ключ `AI_KEY_ENCRYPTION_KEY`). При отсутствии ключа или ошибке AI импорт работает на правилах.
- Если задан серверный `GIGACHAT_API_KEY`, он используется для всех пользователей, а раздел «AI-ассистент» в профиле скрывается.

**Telegram-бот:**

- `/start` и привязка аккаунта;
- загрузка документа (CSV) через бота;
- `/summary` — краткая сводка расходов.

## Переменные окружения

Файл `.env.example` — шаблон для локального запуска и прод-деплоя.

| Переменная | Описание |
|-----------|----------|
| `POSTGRES_USER` | Пользователь PostgreSQL (по умолчанию `postgres`) |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL (по умолчанию `postgres`) |
| `POSTGRES_DB` | Имя базы данных (по умолчанию `finbalance`) |
| `SECRET_KEY` | Секрет для подписи JWT-токенов (сменить в продакшене) |
| `AI_KEY_ENCRYPTION_KEY` | Ключ AES-GCM для шифрования AI-ключей пользователей (сменить в продакшене) |
| `GIGACHAT_API_KEY` | Серверный GigaChat-ключ (Authorization Key). Заполнен — используется для всех пользователей, раздел «AI-ассистент» в профиле скрыт. Пуст — пользователь вводит свой ключ в профиле |
| `BOT_TOKEN` | Токен Telegram-бота. Без значения бот запускается в «спящем» режиме (отключён) |
| `API_URL` | URL бэкенда для бота (по умолчанию `http://backend:8000`) |
| `DEPLOY_PORT` / `DEPLOY_PORT_SSL` | Порт nginx в проде (по умолчанию 80/443) |

Дополнительные настройки backend (`backend/.env.example`): `DATABASE_URL`, `ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`.

## Локальный запуск

### Требования

- Docker и Docker Compose (нужен запущенный Docker Engine);
- Node.js 20+ и Python 3.11+ — только для локальной разработки без Docker.

### Запуск через Docker Compose

```bash
# 1. Создать .env из шаблона
cp .env.example .env

# 2. Поднять весь стек (db, backend, nginx, bot; frontend в dev-профиле)
docker compose up --build
```

- Веб-приложение: после сборки фронтенда в nginx — `http://localhost:8080` (nginx без HTTPS, «dev»-конфиг). Порт публикуется в `docker-compose.override.yml`.
- API backend: `http://localhost:8000` (документация OpenAPI — `/docs`).
- Dev-профиль frontend (bind-mount исходников, `npm start`): включается отдельно, см. сервис `frontend` в `docker-compose.yml` (profile `dev`), по умолчанию `npm run build` встраивается в nginx.

Проверка git: `.env` не коммитится, реальные секреты в репозиторий не попадают.

### Запуск компонентов без Docker (для разработки)

**Backend:**

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
alembic upgrade head
uvicorn main:app --reload
```

**Frontend:**

```bash
cd frontend
npm install
npm start
```

**Telegram-бот:**

```bash
cd bot
pip install -r requirements.txt
# задать BOT_TOKEN и API_URL в .env
python bot/main.py
```

### Тесты

```bash
# Backend: pytest + ruff
pytest
ruff check .

# Frontend
cd frontend && npm run check && npm test
```

### Прод-деплой

Деплой на сервер выполняется через GitHub Actions (`.github/workflows/deploy.yml`): push в `main` или `workflow_dispatch` поднимает стек по `deploy/deploy.sh`, наружу публикуется только nginx (80/443, HTTPS через Let's Encrypt). Полная инструкция и список secrets — в `deploy/DEPLOY.md`.
